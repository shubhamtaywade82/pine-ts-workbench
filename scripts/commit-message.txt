feat: complete the Pine v6 surface (ta.*, str, color, input, log, global, request, strategy, visual, broker)

Reverse-engineering of Pine Script v6 into pine-ts across 9 waves. The
package now exposes the full Pine v6 surface a script can use today:

Wave 1-2 — `ta.*` namespace completion (67/67 functions, 0 planned):
  - Wave 1: `ta.correlation` (paired-non-na Pearson).
  - Wave 2: `ta.alma`, `ta.cci`, `ta.cog`, `ta.max`, `ta.min`, `ta.median`,
    `ta.mode`, `ta.range`, `ta.rci`, `ta.tsi` + variables `ta.iii`,
    `ta.wad`, `ta.wvad`. Plus `ta.pivot_point_levels` (the last `planned`
    entry, returns `PineArray<number>` of 11 levels across 6 chart styles:
    TRADITIONAL, FIBONACCI, WOODIE, CLASSIC, DE_MARK, CAMARILLA).

Wave 3 — Utility namespaces:
  - `str.*` (17 functions incl. `format` w/ ICU-style substitution,
    `tostring` w/ `format.*` specifiers, `match` w/ ECMA-262 regex).
  - `color.*` (7 functions + 17 named constants; `rgb` clamps channels,
    `from_gradient` linearly interpolates between two colors).
  - `input.*` (16 typed input-binding functions: `int`/`float`/`bool`/
    `string`/`color`/`source`/`timeframe`/`session`/`symbol`/`interval`/
    `price`/`qty` + polymorphic `input()`; range clamping, `options`
    validation, host override via `setActiveBindings`).
  - `log.*` + `runtime.error` (per-invocation `LogSink` w/ bar context;
    `RuntimeError` aborts the current bar).

Wave 4 — Global built-ins:
  - `alert`, `alertcondition`, `max_bars_back`, `time`, `time_close`,
    `timenow`, `time_tradingday`, `last_bar_time`, `bool`/`int`/`float`/
    `string`/`color` casts, `timestamp(year, month, day, hour?, minute?,
    second?, timezone?)` constructor. `AlertEvent`/`AlertCondition` sink.

Wave 5 → 8 — `request.*` multi-context execution engine:
  - `RequestEngine` in `src/request/engine.ts` with per-`(symbol,
    timeframe)` cache, alignment logic for `lookahead=off` (non-repainting,
    latest closed HTF bar) and `lookahead=on` (containing bar), per-
    expression result caching by `expression.toString()` (Pine v6 call-site
    identity approximation), `runtime.prepareSecurity(symbol, tf)` host API.
  - `request.security` / `request.security_lower_tf` now dispatch on the
    active engine instead of throwing `RequestNotImplemented`. Calling
    without pre-warming raises `RequestNotPrepared` (no silent fabrication).
  - Provider-limited `request.financial`, `dividends`, `splits`, `earnings`,
    `economic`, `quandl`, `seed`, `currency_rate`, `footprint` still raise
    `RequestNotImplemented` honestly — Pine v6 NEVER invents provider data.

Wave 6 — `strategy.*` engine + broker emulator:
  - `StrategyEngine` class with `entry`/`order`/`exit`/`close`/
    `close_all`/`cancel`/`cancel_all`, market/limit/stop/stop-limit fills,
    OCA groups, pyramiding cap, position reversal, commission (percent/cash)
    + slippage (points/percent), position state (`position_size`,
    `position_avg_price`, `equity`, `netprofit`, `grossprofit/loss`,
    `drawdown/max_drawdown`, `closedtrades_number`, `opentrades_number`),
    `closedtrades.*` / `opentrades.*` accessors, `risk.*` stubs.

Wave 7 — Visual runtime:
  - `plot`/`plotshape`/`plotchar`/`plotarrow`/`plotbar`/`plotcandle`,
    `hline` (returns id)/`fill` (links two hlines)/`bgcolor`/`barcolor`.
  - Drawing objects w/ full create/update/delete lifecycle + `*.all`
    registry: `line`, `label`, `box`, `table`, `linefill`, `polyline`,
    `chart.point` (`from_time`/`from_index`).
  - Renderer-neutral `VisualEvent` stream via `setVisualSink`.

Wave 9a — Live/paper broker adapters (BrokerAdapter boundary):
  - `BrokerAdapter` interface (submitOrder, cancelOrder, getPosition,
    getBalance, onOrderUpdate, optional processBar/close).
  - `PaperBrokerAdapter`: in-memory broker simulating fills against bar
    OHLC w/ the same intrabar path assumption as the emulator (market at
    next-bar open or current-bar close; limit triggers on bar low/high;
    stop on bar high/low; stop-limit triggers then limit). Supports
    pyramiding, reversal, commission+slippage, OCA groups, `onOrderUpdate`.
  - `BinanceBrokerAdapter` scaffold: typed `BinanceTradingSurface` interface
    (newOrder, cancelOrder, getPosition, getBalance, onOrderUpdate) so a
    downstream adapter can be wired to `@nemesis-oss/binance-sdk`'s trading
    surface with real credentials.
  - Wired into `StrategyEngine.setBrokerAdapter(adapter)`; when installed,
    `entry`/`order`/`exit`/`close`/`close_all` forward to the adapter
    (fire-and-forget); `cancel`/`cancel_all` fire-and-forget; the built-in
    emulator is bypassed.
