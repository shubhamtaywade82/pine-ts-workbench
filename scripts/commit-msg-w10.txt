fix(ta): correct ema/rma/tsi/stoch/cci/linreg against PineScript-exported reference vectors

Ecosystem audit wave (see docs/ECOSYSTEM.md): cloned OakScriptJS (MIT,
v0.12.3) and lightweight-charts-indicators (MIT, v0.16.8), audited their
implementations and test suites against pine-ts, and found six real
semantic divergences — all corrected and now pinned bit-for-bit against
actual PineScript output (full-precision reference vectors transcribed
from OakScriptJS's MIT-licensed tests with attribution).

Corrected semantics (each confirmed by Pine-exported values):
- ta.ema: na until the length-th valid bar, seeds with ta.sma (Kahan
  running-sum accumulation order), recurrence (v - prev) * alpha + prev.
  Previously seeded with the first source value with no warm-up.
- ta.rma: Kahan-ordered SMA seed; Pine's exact recurrence
  (v + (length-1) * prev) / length.
- ta.tsi: PC = ta.change(source) (1-bar change, NOT length-bar) and the
  result is a RATIO in [-1, 1], not x100 (v6 reference remark: "the
  built-in returns a ratio, not a percentage-scaled value").
- ta.stoch: zero range and na source KEEP THE PREVIOUS RESULT (previously
  na); peak/valley windows skip na values.
- ta.cci: flat windows (MD <= 1e-10) keep the previous CCI; a first flat
  window gives 0 (previously na).
- ta.linreg: oldest-first x = 1..length accumulation; intercept is the
  fitted value at x = 1 evaluated as sumY/len - (slope*sumX)/len + slope.
